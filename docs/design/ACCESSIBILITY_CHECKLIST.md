# Accessibility Checklist

Last updated: 2026-05-03

## Baseline checklist

- Keyboard reachable controls.
- Visible focus states.
- Screen-reader labels for recording and stop actions.
- `aria-current` or native equivalent for active navigation.
- Error messages attached to controls.
- Permission-denied states explain recovery.
- Recording state is not conveyed by color alone.
- Motion/animation is non-essential and respects platform settings.
- Text contrast meets WCAG AA.

## Voice-specific checklist

- Recording state is explicit.
- Stop action remains available while recording.
- The UI reconciles when recording is interrupted.
- Users can recover from microphone unavailable/offline/model missing states.
- Accessibility claims require user testing before marketing use.
